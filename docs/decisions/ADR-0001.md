# ADR-0001 — Frontend architecture and design reconstruction

- Status: Accepted (Phase 00); backend assumptions pending validation in Phase 01
- Date: 2026-10-30

## Context

The UI/UX was approved as an exported design prototype (16 screens). Prototype pages are
self-contained HTML with inline styles, a proprietary runtime, generated scripts and
embedded fonts. We need a production foundation that can grow into a multi-tenant SaaS.

## Decision

1. **Next.js App Router + React + strict TypeScript** in a single application.
2. **Rebuild the design as React components** instead of shipping or embedding the
   prototype. Tokens are extracted into CSS variables and a Tailwind theme; screens are
   composed from typed primitives (`components/ui`) and feature components.
3. **Tailwind CSS 4** with a token bridge; default palettes are cleared so components stay
   on-token.
4. **Radix UI** for interactive primitives (menu, dialog, tooltip, tabs, toast) and **cmdk**
   for the command palette, rather than hand-written accessibility.
5. **Configuration-driven, role-aware navigation**; role only selects UI configuration.
6. **Preview routes** (`/preview/*`) host demo screens with typed mock data, gated off in
   production unless `ENABLE_PREVIEW_ROUTES=true`.
7. Testing with **Vitest + RTL** (behavior) and **Playwright** (responsive smoke,
   overflow, console errors, screenshots); CI on every PR.

## Why not ship the prototype HTML

- Inline styles and generated markup cannot share state, data or accessibility behavior
  with real features; every change would fork the design.
- Its runtime and embedded assets add weight and an unreviewed dependency.
- Data is hard-coded in markup; the product needs typed data flowing from the server.
- Reconstructing lets us keep visual fidelity (verified by screenshots) while gaining
  type safety, tests and reuse across 16+ screens.

## Consequences

- Visual drift is possible; mitigated by token extraction, screenshot review at four
  viewports, and the design reference map.
- New screens reuse the shell and primitives; Phase 01 swaps the mock workspace context
  for a server-resolved one without restructuring components.
- Backend assumptions (modular monolith, PostgreSQL, `organizationId` scoping,
  per-membership roles) are recorded but not implemented; Phase 01 must confirm or revise.
